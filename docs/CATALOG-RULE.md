# Публикация карточек проектов

Этот каталог — публичная витрина, а не хранилище рабочих материалов.

1. При создании или существенном развитии проекта добавляйте / обновляйте его карточку в `src/projects.json`. Сохраняйте стабильный `id`.
2. Сначала проверьте состояние Git, remote и текущую авторизацию `gh api user --jq .login`. Владелец целевого репозитория — `barsuk-box`, репозиторий — `barsuk-box/projects`.
3. Включайте только безопасное публичное описание: название, назначение, фактический статус, публичные технологии и подтверждённую публичную ссылку. Закрытые ссылки, тексты совещаний, финансовые данные, карточки контрагентов, токены, локальные пути и персональные данные не включайте. Если само существование проекта конфиденциально, публикацию отложите и зафиксируйте причину в закрытых заметках.
4. Карточка содержит поля `id`, `title`, `category`, `status`, `visual`, `description`, `details`, `next`, `tags`, `url`, `updated`. Статусы: `active`, `released`, `planned`. Для идеи не используйте `released`. Значения visual: `audio`, `finance`, `check`, `catalog`, `brand`; выбирайте ближайшее или реализуйте новый вариант в интерфейсе и валидаторе.
5. Подготовьте JSON с одной карточкой, затем выполните `node scripts/upsert-project.mjs <файл.json>`. Скрипт обновляет существующий id или добавляет новый. Проверка структуры не заменяет проверку конфиденциальности человеком / агентом.
6. Выполните `npm run build`, проверьте diff, затем сделайте отдельный коммит только с относящимися изменениями и push. Для параллельной работы используйте отдельный checkout; не сбрасывайте чужие изменения. При конфликте не выполняйте force-push.
7. GitHub Actions собирает сайт после push в `main`. Дождитесь успешного deploy и проверьте URL. Не утверждайте, что карточка на сайте, если выполнен лишь локальный коммит или создан PR.
8. В Obsidian проекта запишите ссылку на карточку/каталог, коммит, результат развёртывания и следующий шаг. При отсутствии доступа сохраните карточку локально и зафиксируйте «ожидает публикации».

Это правило выполняется во время работы Codex над проектом. Оно не является фоновым мониторингом и не запускает автоматический сбор данных компьютера.
